## Исправления по результатам аудита

- `.github/workflows/ci.yml`: Clippy теперь запускается с `--all-features`.
- `scripts/demo.ps1`: проверяются точное название сети, chain ID, версия 1,
  три разных PID, имя процесса `orvexa-node` и их состояние после перезапуска.
  Эти сведения включены в result.json.
- `scripts/demo.ps1`: JSON статуса декодируется из байтов UTF-8 явно. Это устраняет
  ошибочное Latin-1-декодирование тире в названии сети в Windows PowerShell 5.1.
  HTTP API и его JSON-схема не менялись.
- `README.md`: команда Clippy дополнена `--all-features`, добавлены запуск
  и синхронизация третьего узла, описаны дополнительные проверки демо.
- `docs/VALIDATION.md` и этот отчёт: записаны новые результаты проверок.

Код Rust, зависимости, версии, канонические байты, адреса, шифрование, эмиссия,
комиссии, правила валидации блоков и единичный авторитет не изменялись.
SHA-256 всех 36 исходных демо-артефактов совпали с сохранёнными до переименования.

## Точные команды запуска

Для повторного запуска уже созданных и проверенных баз из корня проекта,
**по одной команде в трёх отдельных терминалах**:

```powershell
.\target\debug\orvexa-node.exe run --db .\demo-data\20261017-224714-025c1fae\a.sqlite --listen 127.0.0.1:4242
.\target\debug\orvexa-node.exe run --db .\demo-data\20261017-224714-025c1fae\b.sqlite --listen 127.0.0.1:4243
.\target\debug\orvexa-node.exe run --db .\demo-data\20261017-224714-025c1fae\c.sqlite --listen 127.0.0.1:4244
```

Эти базы уже инициализированы; повторный `init` не нужен. Пароли кошельков демо
не сохраняются. Для собственных кошельков и новой сети следуйте разделу
[ручного запуска](../README.md#ручной-запуск), затем создайте базы узлов B и C
с тем же genesis. Для подготовленных `data/node-*.sqlite` команды:

```powershell
.\target\debug\orvexa-node.exe run --db data\node-a.sqlite --listen 127.0.0.1:4242
.\target\debug\orvexa-node.exe run --db data\node-b.sqlite --listen 127.0.0.1:4243
.\target\debug\orvexa-node.exe run --db data\node-c.sqlite --listen 127.0.0.1:4244
```

Проверка статуса и ручная синхронизация (четвёртый терминал):

```powershell
.\target\debug\orvexa-cli.exe --node http://127.0.0.1:4242 status
.\target\debug\orvexa-cli.exe --node http://127.0.0.1:4243 sync --peer http://127.0.0.1:4242
.\target\debug\orvexa-cli.exe --node http://127.0.0.1:4244 sync --peer http://127.0.0.1:4242
```

Новая полностью автоматическая демонстрация, с созданием отдельных баз:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\demo.ps1
```
