# Оператор приватной тестовой сети v2

Как поднять общую тестовую сеть v2, к которой люди подключаются из ORVEXA
Desktop одной кнопкой. Это тестовая сеть: монеты не имеют ценности, а
производитель блоков один. Он может остановить сеть или не включать чьи-то
переводы, но не может тратить чужие средства, создать атомы сверх эмиссии или
подделать уже подтверждённые блоки (§4–6 [спецификации](PRIVATE_V2_SPEC.md)).

## Что нужно

- Сервер с постоянным адресом и временем работы: VPS за несколько долларов в
  месяц или домашний компьютер, который не выключается. Linux, macOS или Windows.
- Домен и HTTPS. Узел отдаёт API по HTTP; перед ним ставится обратный прокси с
  сертификатом, например Caddy (сертификат Let's Encrypt он получает сам).
- Резервная копия ключа производителя в надёжном месте. Без него сеть не
  сможет выпускать новые блоки.

## 1. Сеть и ключ

```bash
cargo build --release --locked -p orvexa-shielded
./target/release/orvexa-v2-node genesis \
  --to <ovxt1… адрес кошелька, который получит тестовую эмиссию> \
  --producer-key producer.key \
  --name "ORVEXA v2 test" \
  --nodes https://v2.example.org \
  --out network.json
```

`producer.key` создаётся с правами 0600 и никогда не перезаписывается.
`network.json` — публичный файл сети.

## 2. Запуск производителя

```bash
./target/release/orvexa-v2-node run --data-dir /var/lib/orvexa-v2 \
  --network network.json --producer-key producer.key \
  --produce-every-ms 2000 --listen 127.0.0.1:4260
```

Caddy (`/etc/caddy/Caddyfile`):

```text
v2.example.org {
    reverse_proxy 127.0.0.1:4260
}
```

Узел слушает только localhost, наружу открыт лишь порт 443 прокси. Обозреватель
доступен по `https://v2.example.org/`.

Запуск как службы: `systemd`-юнит с `Restart=always` и пользователем без прав
администратора. База (`v2.sqlite`) переживает аварийную остановку (§6.1).

## 3. Дополнительные публичные узлы (необязательно)

Любой может держать ведомый узел: он проверяет всё сам и отдаёт те же данные.

```bash
./target/release/orvexa-v2-node run --data-dir v2-follower --network network.json \
  --follow https://v2.example.org --listen 127.0.0.1:4261
```

Его адрес можно добавить в `nodes` профиля. Chain ID от этого не меняется.

## 4. Как люди подключаются

- **Сейчас:** раздайте `network.json`. В ORVEXA Desktop: «Приватная сеть v2 →
  Загрузить файл сети». Приложение проверит файл и начнёт синхронизацию.
- **Одной кнопкой:** положите тот же файл в
  `crates/orvexa-shielded/networks/default.json` и выпустите новую версию
  приложения. В ней появится кнопка «Подключиться к тестовой сети ORVEXA v2»,
  а обновление доставит её всем через автообновление ([UPDATES.md](UPDATES.md)).

## Ограничения

- Один производитель: если сервер выключен, новые переводы не подтверждаются;
  данные у всех участников сохраняются. Несколько валидаторов — этап 8 плана.
- Узлы участников не принимают входящих соединений и не раздают блоки другим.
- IP-адреса участников видны серверу, к которому они подключены.
