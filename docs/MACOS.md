# ORVEXA на Mac

Нативный код macOS добавлен в исходники: Tao + системный WKWebView, без
встроенного Chromium или WebView2. Поддерживается **macOS 14 и новее**.
Универсальная сборка объединяет Apple Silicon и Intel; доступны и отдельные
архитектуры. Проверенного готового архива Mac пока нет. Не скачивайте Windows
EXE для запуска в macOS.

На Windows нельзя подтвердить работу окна AppKit, загрузку файлов, подпись,
восстановление WebKit-профиля или расход энергии Mac. До выполнения проверки
на настоящем Mac сборка считается неподтверждённой. Workflow
`macOS native preview` собирает universal `.app` и проверяет встроенный
консольный контроллер, но не заменяет ручную проверку окна.

## Подготовка инструментов сборки

Нужны Xcode Command Line Tools, Rust/rustup и Node.js 24+ с npm. Это инструменты
разработчика: пользователю готового `.app` они не нужны. Интернет используется
при получении исходников и зависимостей, не как сервис работы сети.

```bash
xcode-select --install
git clone https://github.com/waxiechc/orvexa.git
cd orvexa
cargo install wasm-bindgen-cli --version 0.2.129 --locked
bash scripts/package-macos.sh universal
```

Команда установки Xcode выполняется один раз, если инструментов ещё нет.
Сценарий сам устанавливает нужные Rust targets и отдельный Wasm toolchain
1.93.0. Запускайте его после завершения установки Xcode. Он проверяет версии,
собирает интерфейс, встраивает Wasm и лицензии, создаёт `ORVEXA.app`, ZIP и
`SHA256SUMS-macOS.txt` в новом каталоге `release/macos-*`.

Для одной архитектуры:

```bash
bash scripts/package-macos.sh arm64  # Apple Silicon
bash scripts/package-macos.sh x64    # Intel
```

Сборка использует ad-hoc подпись для целостности. Это **не** Developer ID и не
нотаризация Apple. Gatekeeper может заблокировать скачанную неподписанную или
ненотаризованную программу. Не отключайте Gatekeeper целиком. Для будущего
распространения нужны отдельная проверка и решение о подписании; членство в
Apple Developer не требуется для локальной сборки. Если у оператора уже есть
идентичность подписи, её можно явно передать через `ORVEXA_SIGN_IDENTITY`.
Сценарий не покупает сертификаты и не отправляет приложение Apple.

## Запуск и данные

Откройте созданный `ORVEXA.app` через Finder или командой `open` с его точным
путём. Для параметров запуска:

```bash
open /путь/к/ORVEXA.app --args --listen 127.0.0.1:4252
```

Основной язык — русский, переключатель RU/EN находится в шапке. Кошелёк,
обозреватель и узел используют тот же протокол v1, что и Windows. Для общей
сети нужны настоящие `genesis.json`, `network.json` и доступные участники.
Полный узел не получает права authority или награды автоматически.

Сетевые данные: `~/Library/Application Support/ORVEXA`. Хранилище зашифрованных
кошельков обслуживает WKWebView; его постоянный идентификатор связан с
каноническим каталогом профиля. Разные `--data-dir` изолируют профили.
WebKit не обязан хранить данные внутри подкаталога `webview`, как в Windows.
Не переносите/не очищайте профиль без проверенного резервного файла кошелька.
Смена UI-порта меняет origin — для доступа к кошельку понадобится его копия.

Меню «Правка» предоставляет ⌘C, ⌘V, ⌘X и ⌘A. ⌘Q останавливает узел и завершает
приложение. Закрытие единственного окна в этой версии также завершает работу
узла. Кнопка резервного копирования сохраняет зашифрованный файл через WebKit
в системный каталог загрузок. Пароли и ключи не проходят через node API.

## Изменения для нагрузки и совместимости

- Системный WebKit вместо поставки отдельного браузерного движка.
- Нативный исполняемый код обеих архитектур в universal `.app`, без требования Rosetta.
- Два Tokio worker вместо выделения потока на каждое ядро CPU.
- Опрос интерфейса приостанавливается, когда документ скрыт, и возобновляется
  при возвращении. Сам узел продолжает сетевую работу независимо от опроса.
- Системная типографика, масштабирование Retina, обычная рамка окна и тёмный фон.
- Шифрование выполняется в отдельном короткоживущем Wasm worker.

Это конкретные изменения реализации, **не измеренный выигрыш** в CPU, RAM или
времени работы батареи. Такие показатели требуют замеров на оборудовании.

## Проверка на настоящем Mac

1. Запустить `.app` из Finder без исходников рядом; создать кошелёк с русским
   названием, скачать зашифрованную копию и восстановить её в другом профиле.
2. Проверить выбор файлов, ⌘C/⌘V, QR, переключение RU/EN и сохранение языка.
3. Импортировать общие публичные файлы, сверить chain ID, запустить узел.
4. Перевести A → B → A, найти настоящие хеши в обозревателе; сверить комиссии.
5. Перезапустить приложение и проверить адрес, баланс, tip и идентификатор узла.
6. Скрыть окно: убедиться, что UI перестал опрашивать API, а P2P продолжает работу.
7. Проверить ⌘Q, повторный запуск, второй экземпляр с тем же профилем, работу
   на Apple Silicon и Intel, восстановление после обрыва сети.

этапом. [Модель угроз](../THREAT_MODEL.md) и [план](PLATFORM_PLAN.md) остаются в силе.
