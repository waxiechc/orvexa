# Автообновление ORVEXA Desktop

## Как это работает у пользователя

- В «Настройки → Обновления» есть переключатель **«Автоматические обновления»**
  (включён по умолчанию). Когда он включён, приложение раз в 6 часов (и через
  20 секунд после запуска) проверяет новую версию и скачивает её в фоне.
  Когда выключен, приложение само не обращается к серверу обновлений; кнопка
  «Проверить сейчас» работает всегда.
- Когда новая версия скачана и проверена, в углу окна появляется уведомление
  «Новая версия … — Перезапустить и обновить / Позже».
- Установка только по кнопке: приложение заменяет себя проверенной сборкой,
  перезапускается с теми же параметрами и удаляет старую копию после
  успешного старта. Кошельки, сеть и настройки не затрагиваются.
- Сборки для разработки не обновляются.

## Почему этому можно доверять

- Манифест `docs/updates/preview.json` подписан Ed25519 ключом выпуска;
  открытый ключ (`crates/orvexa-update/update-key.pub`) вшит в приложение.
  Подменённый сайт, зеркало или сеть не могут заставить установить другое.
- Каждый файл проверяется по размеру и SHA-256 из подписанного манифеста и
  скачивается только с `github.com/waxiechc/orvexa/releases/download/…`.
- Версия не может уменьшиться (самая новая увиденная запоминается), а
  манифест имеет срок действия (по умолчанию 30 дней).
- На macOS новый бандл проверяется `codesign --verify --strict` и должен
  нести ту же версию, что в манифесте; на Windows — заголовок x64.
- Установить обновление может только окно приложения (токен сессии).

Проверено: Rust-тесты подписи, версий, отката, контрольной суммы и подмены
бандла; на macOS — полный прогон на собранных приложениях (preview.5 нашла,
скачала, проверила и установила preview.6, перезапустилась с теми же
аргументами). На Windows замена `ORVEXA.exe` собрана, но не запускалась.

## Как выпустить обновление

Ключ выпуска лежит в `~/.orvexa-release/update.key` (создан командой
`orvexa-release keygen`). **Сделайте его резервную копию** в надёжном месте
(зашифрованный диск, менеджер паролей). Если ключ потерян, установленные
приложения новые обновления не примут — придётся раздать новую версию
вручную. Никому его не передавайте и не кладите в репозиторий.

1. Соберите релизы с новой версией:
   ```bash
   ORVEXA_VERSION=0.1.0-desktop-preview.5 bash scripts/package-macos.sh universal
   ORVEXA_VERSION=0.1.0-desktop-preview.5 bash scripts/package-windows-cross.sh
   ```
2. Опубликуйте GitHub-релиз `v0.1.0-desktop-preview.5` с файлами
   `ORVEXA-macOS-universal.zip` и `ORVEXA.exe` (имена должны совпадать).
3. Подпишите манифест:
   ```bash
   cargo run --release -p orvexa-update --bin orvexa-release -- manifest \
     --key ~/.orvexa-release/update.key --release 0.1.0-desktop-preview.5 \
     --mac release/macos-…/ORVEXA-macOS-universal.zip --win release/windows-…/ORVEXA.exe \
     --notes-ru "Что нового" --notes-en "What's new" --out docs/updates/preview.json
   ```
4. Закоммитьте `docs/updates/preview.json` и `preview.json.sig` в `main` —
   GitHub Pages опубликует их, и приложения увидят обновление.

Публиковать манифест нужно **после** загрузки файлов в релиз и хотя бы раз в
30 дней (или выпускать с `--days` больше), иначе приложения покажут, что
информация об обновлении устарела.

## Конфиденциальность

Проверка обновлений — единственное фоновое обращение приложения в интернет
(GitHub Pages и GitHub Releases видят IP и время запроса). Выключите
«Автоматические обновления», если это нежелательно.
