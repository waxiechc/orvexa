# Стенд P1: `orchard = "=0.16.0"` (Ironwood v3)

Изолированная проверка кандидата приватного backend для этапа 2 плана
([PRIVACY_TEST_PLAN.md](../../docs/PRIVACY_TEST_PLAN.md), P1). Стенд **не входит**
в workspace v1: у него свой `Cargo.toml` с пустым `[workspace]` и свой
`Cargo.lock`. Протокол v1, форматы кошельков и `Cargo.lock` v1 не менялись.
Это не адаптер ORVEXA, не формат транзакции и не решение о выборе библиотеки.

## Что именно проверяется

- `BundleVersion::ironwood_v3()`, `OrchardCircuitVersion::PostNu6_3`, sighash
  через `TxVersion::V6`; features `std`, `circuit`, `multicore`.
- Настоящие Halo2-доказательства и подписи RedPallas, без mock-verifier.
- Финансирование: coinbase-подобный bundle только с выходами, затем дерево
  commitments (`shardtree`), anchor и witness для каждой note.
- Перевод A → B: `k` spends и `k` outputs (`k` = 2, 4, 8 actions), комиссия 10,
  `value_balance = 10`. Получатель находит свои notes пробной расшифровкой,
  посторонний кошелёк C — ничего.
- Каждая фаза запускается в отдельном процессе, поэтому пиковая память
  считается по фазе. Каждое доказательство создаётся и проверяется 3 раза.

Запуск:

```bash
cd research/orchard-eval
cargo build --release --locked
./target/release/orchard-eval > results/<машина>.json
```

## Отрицательные проверки

| Случай | Результат библиотеки |
|---|---|
| Корректный bundle | принят |
| Один бит доказательства изменён | proof отвергнут; пакетная проверка тоже `false` |
| Доказательство обрезано | proof отвергнут |
| Подписи сверяются с другим sighash | spend-auth подпись отвергнута |
| Value balance изменён после подписи (новый sighash) | spend-auth подпись отвергнута |
| Value balance изменён, sighash прежний | binding-подпись отвергнута |
| Verifying key другой версии circuit (`FixedPostNu6_2`) | proof отвергнут |
| Подпись чужим spend-ключом | builder отказывается: подписи не хватает |
| Witness не соответствует anchor | builder: `AnchorMismatch` |
| Два выхода по `u64::MAX` | builder: `ValueSum(Overflow)` |
| **Одна note дважды в одном bundle** | **builder принимает, проверка проходит, nullifier повторяется** |
| **Одна note в двух bundle** | **оба проходят, в том числе вместе в одной пакетной проверке; nullifier общий** |
| **Выходы больше входов** | **проходит, `value_balance = −40000`** |

## Что из этого следует для узла ORVEXA

1. Библиотека проверяет доказательство и подписи одного bundle. **Защиту от
   двойной траты она не обеспечивает.** Узел обязан хранить множество
   nullifiers и отвергать повтор внутри bundle, внутри блока и между блоками,
   атомарно с применением блока (этап 4 плана).
2. **Отрицательный value balance означает, что стоимость входит в пул.**
   Библиотека это допускает. Правила ORVEXA должны явно запрещать это или
   ограничивать заранее определённым выпуском, иначе получится эмиссия из ничего.
3. Anchor должен быть одним из корней дерева, принятых узлом. Builder проверяет
   только согласованность witness, которые ему передали.
4. Версия circuit и sighash должны быть зафиксированы правилами сети: ключ
   другой версии доказательство не принимает.
5. Создание доказательства на Apple M4 занимает около 0,3 с на action и
   растёт линейно. Проверка — миллисекунды, сканирование — доли миллисекунды
   на action. На слабом ПК цифры нужно измерить отдельно.

## Зависимости, лицензии, advisories

- Граф стенда: 103 пакета для всех платформ ([results/licenses.json](results/licenses.json)).
  Все лицензии разрешительные: MIT/Apache-2.0 и их варианты, `subtle` под
  BSD-3-Clause, по одному пакету под Unlicense/MIT, Zlib, CC0/MIT-0 и Unicode-3.0
  (в составе двойной лицензии). У одного пакета есть вариант LGPL-2.1-or-later,
  но его можно взять под MIT или Apache-2.0.
- `cargo audit` 0.22.2 с базой RustSec от 2026-10-17: 0 уязвимостей,
  0 предупреждений ([results/rustsec-audit.json](results/rustsec-audit.json)).
- Windows x64: стенд собирается кросс-компиляцией (`cargo xwin build --release
  --target x86_64-pc-windows-msvc`). **На Windows он не запускался**, а замер
  памяти там не реализован (`peak_rss_bytes: null`).

## Что не закрыто (P1 не завершён)

- **P1-02, покрытие аудитом.** В CHANGELOG 0.16.0 нет сведений об аудите
  Ironwood и `PostNu6_3`. Какие части покрыты независимым аудитом, этот стенд
  не устанавливает. Это нужно выяснить по первоисточникам до решения.
- **P1-05:** замеры на обычном Windows-ПК и на Intel Mac. Пакетная проверка
  нескольких разных bundle и стоимость сканирования длинной цепочки.
- **P1-04:** разбор повреждённых сериализованных данных. Сериализации в самом
  crate нет, поэтому это проверяется вместе с будущим форматом ORVEXA.
- **P1-06:** сравнительная база Monero не собиралась.
- **P1-07:** решение go/no-go не принято. Этап P2 автоматически не начинается.
